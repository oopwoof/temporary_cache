## 一、这是第二轮

第一轮盲评给了 7/10、建议进入下一轮，提出**六条事实性问题**。我把每一条都实际复现了一遍，**全部属实，没有一条误报**，并据此做了修改。这一轮想知道的是：修改本身对不对，以及还剩下什么。

### 上一轮的六条与改法

| 上一轮指出的 | 复现结果 | 改法 |
|---|---|---|
| 文档称参与人数为"去重人数"，但数据只有天×点位汇总，跨天求和必然重复计人 | 属实，最致命的一条 | **加了 HyperLogLog 草图**。没有选"改称谓"这条便宜路 |
| 持续异常只在开始日建事件，事件表按开始日过滤 | 属实。一条 7/18 起持续 60 天的异常，在默认 30 天视图里预警在报、事件表查不到 | 事件带起止日期，改为**区间相交**过滤 |
| P95 是估算却写成"都是准的"；"14 档"实为 13 档 | 属实。默认切片估算 15.7s vs 真实 15.39s，单日切片最大偏差 +1.27s，且**偏差恒为正** | 一律标注估算，写明偏差方向的成因，档数从配置注入 |
| "仍在发生"只代表所选范围末日越界；设备状态读数据集末日快照却与所选日指标并列 | 属实 | 拆成两个标记；设备表最新日用心跳、历史日按当天数据推导且心跳列置空 |
| 漏斗从"参与"直接跳到"生成成功"，gen_users 已存在却没用 | 属实。合并的那步里 24.4% 是没发起生成、6.3% 是发起了没成功 | 漏斗补成五段 |
| 自称"看板与文档引用同一份阈值"，实际是手写字符串 | 属实，过度声明 | 改成模板 + 注入，这句话才成立 |

### 为什么选了 HyperLogLog 而不是改称谓

"改叫人次"半小时就能做完，也诚实。但面试官一定会追问"那怎么才能拿到真去重"，这个答案我觉得应该写在代码里而不是靠嘴说。而且它和已有的"P95 存直方图"是同一个思路的两个实例——**可加的量存标量，不可加的量存可合并的结构**——放在一起，这份作业才有一条贯穿的设计主张。

代价是数据体积从 372KB 涨到 1.0MB，以及 KPI 首位放了一个估算值。这两点都值得你质疑。

## 二、修复过程中自己又抓到的两个 bug

都是写校验才暴露的，不写就会**安静地输出错误数字**：

- **哈希混合不足**。HLL 最初用裸 FNV-1a，对 `u0000001` 这类连续 ID，**n=300 时估算偏低 49%**，寄存器下标卡方 2473（理想 1024）。加 murmur3 的 fmix32 收尾后最大误差 3.9%、卡方 1093。
- **估算越界**。单日切片估出的去重人数**大于人次**，人均显示成 0.98 次。改为用两个已知硬约束夹逼（上界＝人次，下界＝单格去重最大值），且只有一条记录时直接取精确值。

## 三、这一版做过的验证

`bash scripts/verify.sh` 一条命令跑完，**60 项断言全绿**：

- 数据可复现（连跑两次 diff 为空）
- 4 种筛选组合下 KPI 每个数字与独立 Python 实现一致
- 漏斗五段与独立实现一致且单调递减
- 上一轮的每个复现用例都有对应断言（持续异常在 7/14/30/60 天视图下都查得到；设备表两种日期下的状态、列头与心跳列）
- **Python 与 JS 两端的 HLL 对同一批草图算出相同结果**（小数点后 4 位）
- 480 条记录与 44 条事件的不变量检查（去重≤人次、分小时之和＝人次、成功+失败＝请求、审核三项之和＝送审量等）
- 零外部网络请求、900px 无横向溢出、无 console 报错
- 阈值单一来源：改生成器里的阈值 → 重跑 → 文档数字随之改变（已实测）

**这些验证证明的是两套实现算出同样的数，不证明口径定义本身合理**——后者仍然需要你判断。

## 四、仍然没解决的

- **转化率的分母还是人次**，不是去重人数。给扫码、分享各配草图会让体积再翻倍，收益不匹配。文档写明了分母口径，但"去重 KPI + 人次分母"并存是否会让运营看混，我没有把握。
- **去重人数与 P95 都是估算**。误差已实测（HLL 在 200 个切片上中位 1.74%、最大 6.66%）并写进文档，但把估算值放在 KPI 第一位仍是个可争议的选择。
- **复玩率只能给到"人均参与次数"**，给不出"参与≥2 次的人占比"——HLL 只能估基数，估不了频次分布。
- 无后端、权限模型、派单闭环；无单元测试（正确性依赖 `verify.sh` 的 60 项断言）；未做完整无障碍审计；无移动端专门布局。
- **阈值仍然是拍的**（90% / 12s / 15% / 95% / 30%），没有行业基准或历史基线支撑。这是上一轮就提过、这一轮仍然没解决的。
- 模拟数据里各指标的相关性结构、以及用户回访行为（18% 同点位回头、3% 同城跨点位、回访聚集在最近 5000 人次内）都是人为设定的。
