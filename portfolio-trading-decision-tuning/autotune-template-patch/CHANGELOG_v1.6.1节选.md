## v1.6.1 — 2026-09-18

判分包的**参评方数解除写死**。起因：`portfolio-trading-decision` 实例要把回归底线
（裸模+原 skill）和候选放进同一把尺子判，才能核 manifest 里 `hard: {no_loss_to: base+skill}`
那条硬条件——而它优先于主判据，不核就不能说准出。

打包脚本本来就支持 6 方（`labels = "甲乙丙丁戊己"`），**卡住的是判分方读到的文字**：
三个 prompt 文件里 8 处硬写「四份 / 四方」，其中 `05_judge.md` 的
`四方排序 + 1-5 分` 还是 selftest 用来区分 scoring / pairwise 两套协议的**模式标记**。

### 改了什么

| 文件 | 改动 |
|---|---|
| `prompts/05b_judge_subagent.md` | 「四份答复（甲/乙/丙/丁）」→ `{n_parties}` 份答复（`{labels}`）；「四方从好到差」→「{n_parties} 方从好到差」；「同一题里四份答复」→「各份答复」 |

| `scripts/make_g0_pack.py` | 渲染 `{n_parties}` / `{labels}`（与已有的 `{domain}` 同一处）；包内 README 的标题与标签列表按实际方数生成 |
| `gates/parallel.yaml` | 「同一题的四方必须在同一次调用里判完」→「各方」。两个外发包都从它渲染，逐字一致仍成立 |
| `scripts/selftest.sh` | **模式标记断言随之改成 `多方排序 + 1-5 分`** |

### ⚠ 这次改动动了检查器本身

`selftest.sh` 里的模式标记断言是跟着 `05_judge.md` 一起改的。按经验沉淀第 12 条，
**改了检查器就必须标红上卡，不能自己判自己通过**。本次改动前后都跑了 selftest：
改前 38/38，改后 38/38。但「38/38 通过」这个结论本身有一处是我改过的断言，
**需要人工复核这一处**：确认 `多方排序 + 1-5 分` 仍然只出现在 scoring 段、不出现在 pairwise 段。

### 历史实例要不要重跑

**不要。** 这次改的是判分包里对方数的**表述**，没有改：判定顺序、打分档位、平局口径、
硬门禁定义、三轮独立机制。四方包重新生成后渲染出来的文字与 v1.6.0 在语义上等价
（「四方排序」→「多方排序」，实际方数仍由 `--parties` 决定）。
已判完的历史读数继续有效，**不需要重评**。

### 同步

所有实例应同步 `prompts/05*.md`、`scripts/make_g0_pack.py`、`scripts/selftest.sh`、
`gates/parallel.yaml` 四处。**不要整文件覆盖实例的 `gates/thresholds.yaml`**（经验沉淀 25）。

## 待补：v1.6.2 候选（runs/3 实测暴露，尚未写成 diff）

`scripts/check_judge_quality.py` 的「三轮独立性」检查有两个漏洞，runs/3 各踩一个：

### 1. 只打印一个口径，会导出相反的结论

现在只报「三轮给出的分相同的占比」。runs/3 实测：

| 口径 | 三轮完全相同的题 |
|---|---|
| 按槽位字母（甲乙丙丁戊） | 0/8 |
| 按答案键映射回候选 | 8/8（120 格逐格相同） |

只看前者 → 「三轮完全独立，很好」；只看后者 → 「三轮是一份拷贝」。
**两个数说的是不同的事，必须都打印**：
前者低 = 判分方没照字母抄（好事，映射正确）；后者高 = 三轮不独立（坏事）。

改法：`_independence()` 同时算 by-slot 与 by-candidate 两个占比，
**by-candidate ≥90% 判硬不合格，by-slot ≥90% 单独判「疑似照字母抄」**（两种病，不同处置）。

### 2. 独立性只查分数，不查评语——灵敏度不够

分数只有 5 档，三轮撞上同一组数并非不可能。runs/3 的决定性证据是
`why_first` / `why_last` / `hard_gate_hits` 的**中文评语逐字相同 8/8 题**。

改法：把 `why_*` 的 `quote` + `why` 拼串后按题次比三轮，
**逐字相同 ≥50% 的题即判「三轮非独立」**，比分数口径先触发。

### 3. 顺带一条：引句回查失败的三条是同一条

现在按 (轮, 题, 方, 引句) 逐条报，runs/3 的 3 条报错其实是**同一条引句在三轮各出现一次**。
报「3 条」会让人以为有三个独立问题。改为**按引句去重后报「1 条（出现 3 次）」**。

> 经验沉淀第 12 条：改检查器要标红上卡。这三条都**没有**动实例里已判完的读数，
> 只改报表形态与触发条件；写成 diff 后须先在 runs/1~runs/3 三批历史回包上回放，
> 确认 runs/1、runs/2 仍是退出码 1、runs/3 仍是退出码 2，再上卡。
