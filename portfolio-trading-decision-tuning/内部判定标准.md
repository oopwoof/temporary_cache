# 内部判定标准（两条轨）

**规矩：内部用抗噪指标判断方向，最终交付按需求方的判据报。** 两者都出，不互相替代，
也不拿内部指标去改需求方的结论。

## 轨一｜内部主判据：载体落地（判分噪声 = 0）

`scripts/carrier_landing.py`。完全机械，不经过判分方，**同一批答复跑十次结果一样**。

```bash
python3 scripts/carrier_landing.py --run <跑题回包> --round 1 --out runs/2/载体落地.md
```

为什么它有资格当主判据：

1. **runs/1 证明了载体与胜负直接相关**——有载体的两条（工作簿公式、相邻一手验证）
   拿下全场最高分，纯措辞的几条落地 0~2/8 且吃了两处硬门禁；
2. **它独立复现了判分方的结论**：在 v3.0 上跑，它自己抓出 case01「正文声称 8 件、
   实际产出 6 件」——正是判分方记我们硬门禁的那一条，而它完全没看判分结果；
3. **v4 的五条改动全是载体**，所以这一轮的验收本来就可以机械化。

阴性对照（v3.0，五条载体都还没有）：

| 载体 | v3.0 落地 | v4 目标 |
|---|---:|---|
| C-03 决策摘要表在开头 | 2/8 | 8/8 |
| C-01 自检回执表存在 | 0/8 | 8/8 |
| C-01 回执填了件数 | 0/8 | 8/8 |
| C-02 反解值列存在 | 1/8 | 有硬约束的题全出 |
| C-02 反解值填了数量 | 0/8 | 同上 |
| C-04 规则表有口径列 | 2/8 | 有规则的题全出 |
| C-05 写出相邻一手验证 | 1/8 | 涉及最少数量的题全出 |
| 交付声明 = 实际件数 | case01 ✗ | 全对 |

**内部判断规则**：v4 的五条载体若落地率没有明显高于上面这列，就是改动没生效，
不必等判分结果——直接进下一轮工单。

## 轨二｜抗噪的内部辅助指标（用判分数据，但不用脆弱的统计量）

判分噪声分三层，**不要混用**：

| 层级 | 噪声 | 能不能用 |
|---|---:|---|
| 单格（方×题单题分数） | 0.72 / 0.37 | **不能**做单题结论 |
| 判据统计量（8 题均分差） | 0.12~0.21 | 可以，但要带 ±0.2 区间 |
| 逐题符号一致性（三轮都赢才算赢） | —— | **推荐**，见下 |

**逐题符号一致性**：一题只有三轮都赢才记「稳赢」，三轮都输记「稳负」，其余记「摇摆」。
runs/1 实测：第一包 稳赢 2 / 稳负 4 / 摇摆 2；噪声包 稳赢 3 / 稳负 3 / 摇摆 2。
比「超过题数」稳得多，因为它把噪声题显式隔离出来而不是强行归类。

内部报法：**稳赢 / 稳负 / 摇摆 三分类 + 均分差±区间**，不报单轮的精确分差。

## 轨三｜最终交付：按需求方的判据原样报

`scripts/score_release.py --per-pass`，判据一条不改：
对 base 分差 ≥0.4、胜率 >60%、超过题数 ≥6/8；对 WB 胜率 >60% 或松弛路径；
硬条件对 base+skill 零负场。**逐轮 + 均值都报。**

附两条必须一起给的说明（否则是在高估结论）：

1. **噪声底同表报**：判据统计量噪声 0.12~0.21，门槛 0.4 ≈ 2~3 倍，
   所以 0.3~0.5 的读数标为「落在噪声内，不可据此判定」；
2. **「任一轮达标」的系统性偏移**：三轮取最大，平均高估约 +0.18，
   相当于把 0.4 的门槛降到约 0.22。这条已写进 `runs/1/给需求方_判分噪声反馈.md` 请需求方定；
   **在他们定之前，交付结论仍按现行口径报，只是并列标注均值口径下的结果。**

## 三条轨怎么一起用

| 情况 | 怎么判 |
|---|---|
| 载体落地率高 + 交付判据达标 | 真达标，可以准出 |
| 载体落地率高 + 交付判据在 0.3~0.5 | 内部认为方向对，**交付结论如实写"未达标"**，同时报噪声区间与载体数据 |
| 载体落地率低 + 交付判据达标 | **警惕**：可能是噪声撞上了。建议重判一轮再定 |
| 载体落地率低 + 交付判据未达标 | 改动没生效，直接进下一轮工单 |
