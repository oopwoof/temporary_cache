## 六、这一包在 `ranking.json` 里埋了两个字段，请原样处理

同一种失效已经出现两次（三轮被合成一轮）。前一包我们在说明里写了整整一节、
还加了两条回执要求，回包里没有任何回执。所以这一次改成**机械可核**的做法。

每个 `pass<N>/case<NN>/ranking.json` 已经**预先放好**，里面多了两个字段：

```json
{
  "pass_token": "a925dc94bb2b1506",   // ← 原样保留，一个字符都别改
  "longest_label": "",                 // ← 请填
  ...其余字段照常填
}
```

### 6.1 `pass_token`：原样保留

它是我们预置的随机串，**每一轮每一题都不同**。
请在**已有的这份文件上填**，不要新建、不要从别处复制一份覆盖过来。
它只证明一件事：这份 `ranking.json` 来自它所在的那一轮的目录。

### 6.2 `longest_label`：填「本题里字数最多的那份答复的标签」

就是 `pass<N>/case<NN>/答复/` 下五份 `.md` 里**字符数最多**的那一份的标签（甲/乙/丙/丁/戊）。
按字符数，不按文件字节数。

**这不是判分，不影响任何分数**，也不需要你判断好坏——
它只是一个我们这边能独立复算的读数，用来确认填表的人确实打开了**这一轮**的答复。
标签每轮是重新洗过的，所以正确答案逐轮不同。

顺手就能填，不用额外花时间。**填错了我们会告诉你，不会直接作废。**

### 6.3 说清楚这两个字段**不能**证明什么

它们证明不了「三轮是各自独立判的」——
判一次、再按每轮的洗牌把结果映射过去、顺手把这两个字段填对，照样能通过。

**我们真正的判据仍然是内容级的**：按候选归一之后，三轮的分数是不是逐格相同、
评语原句是不是逐字相同。前两次就是这么查出来的。

之所以还是要埋这两个字段，是因为它们能告诉我们**塌在哪一层**：

| 现象 | 说明塌在哪 |
|---|---|
| `pass_token` 对不上 | 文件层——某一轮的 `ranking.json` 是从别处整份复制过来的 |
| 两个字段都对，但内容级三轮全同 | 映射层——判了一次，按洗牌映射成了三份 |
| 两个字段都对，内容级有分歧 | 正常 |

**知道塌在哪一层，我们才能提对的要求，而不是每次都笼统地说「请独立判」。**
