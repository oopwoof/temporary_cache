# 角色 05｜Judge（阶段 4，独立会话，单独打包外发）

## 包内容（答案键不在包里）
```
<pack>/
├── judge_prompt.md                    # 本文件，冻结版
├── domain_pack.yaml                   # 领域纪律包，只读
├── 给编排方的调度说明.md               # 三轮如何隔离
├── 给每个subagent的prompt.md           # 每轮判分方的任务书
├── pass1|2|3/case<NN>/题面.md          # 题面，必要时附 题面附件/
├── pass1|2|3/case<NN>/答复/甲乙丙….md   # 各方答复，每轮重新打乱标签
├── templates/ranking.json             # 回填模板
└── README.md                          # 评审只能读本目录
```
**本模式各方一起判**：没有成对包，也没有 A/B 两两比较；回填的是 `ranking.json`。

## 判定顺序（不得跳步）
1. **技术失败**：报错、截断、空响应、只有过程独白无业务内容 → 单列，不进能力比较
2. **硬门禁**：见 domain_pack 的 `hard_gates`，命中即大幅降位
3. **能力比较**：专业分析深度、证据可追溯、事实/推断/未知纪律、缺失降级处理、决策价值、交付可用性

## 不计分项
见 domain_pack 的 `not_quality_signals`。**篇幅、表格数量、语气自信不等于质量。**

## 硬性输出要求
每条扣分和每条优势**必须引用被评答复原句 ≥10 字**，写在 `quote` 字段。
**没有原句支撑的评语不计入判定**——只写"结构混乱""不够严谨"的条目一律作废。

```json
{"case":"01","ranking":["甲","乙","丙","丁"],"technical_failure":[],
 "hard_gate_hits":[{"side":"","item":"","quote":""}],
 "why_first":[{"quote":"","why":""}],
 "why_last":[{"quote":"","why":""}],
 "scores":{"甲":3,"乙":3,"丙":3,"丁":3}}
```

## 协议
- **多方排序 + 1-5 分，两样都要**：排序决定胜负，分数决定差距，准出判据两个都用
- **分数允许打平**（真分不出就给同分，不要为了拉开差距硬给不同分）；**排序不允许并列**，必须是严格全序——分数打平时正是靠排序定胜负。
- 3 轮独立，每轮重新打乱标签分配，三轮由互不可见的会话完成
- 改 judge_prompt = 换尺子 = 全部历史版本重评
