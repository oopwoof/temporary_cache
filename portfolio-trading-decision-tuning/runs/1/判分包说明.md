## 三、无平信号：这一包本身就带，不用额外要

之前提的「8 个 skill 全卡在 ≥6/8 超过、根因是 29% 平局率」——这一包的设计已经把它解决了：

- `judge_prompt.md` 要求**从好到差的完整排序**（严格序，不允许并列）→ 这就是无平信号；
- 同时要 **1-5 分**绝对打分（允许同分）→ 这是分差信号。

`gates/thresholds.yaml` 里 `winrate_tie_mode: rank` 已经设成「分数打平时看名次」，
两个信号都会被用上。**不需要再向判分方追加要求**，照包里的措辞发即可。

## 七、准出判据（回来之后对照这个看）

| 对手 | 条件 | 说明 |
|---|---|---|
| 对 base（裸模） | 均分差 ≥0.4 **且** 胜率 >60% **且** 8 题至少 6 题**严格超过** | 三条全过 |
| 对 WB | 胜率 >60%；**或** 对裸模分差 >0.5 且对 WB 胜率 ≥50% | 二选一 |

两条路径须在**同一轮内同时**满足；三轮里**任一轮满足即可**。
gpt 参与比较但不进判据。**胜率必须同时报口径**（平算半 / 不计平 / 胜总），不标口径的胜率作废。

起点提醒：上一轮 v1.0 的读数是对裸模分差 **−0.75**、超过题数 **1/8**、对 WB 胜率 62%。
要达标，分差要从 −0.75 抬到 +0.4 以上，**净变化 ≥1.15 分**。

## 七之二、回归底线怎么核

`base+skill` 在包里，所以 `hard: {no_loss_to: base+skill}` 本轮**可以核**：
逐题看 ours 与 base+skill 的名次与分数，**任一题 ours 低于 base+skill 即该轮不达标**
（这条优先于第七节的分差/胜率判据）。三轮各自核，与主判据同轮同时满足才算这一轮达标。

## 七之三、本轮读数怎么挂到历史刻度上（「不重评历史」为什么不等于没有锚）

「历史实例不重评」说的是**别的 skill 已经判完的轮次**（固收、保险等）——那是模板升版的跨 skill 可比性问题。
**本 skill 的历史四方不在此列：它们正在这一包里被重判。**

包里的 base / base+skill / WB / gpt 就是当年专家评过的**同一批答复**，一字未改。
所以定位不靠「把新数字对到旧数字上」——那两把尺子本来就不同（人类专家 vs LLM judge），
重评历史也修不好。定位靠的是**四方锚点在同一把尺子上重新测一遍**：

1. 判分方给出五方排序 → 剔掉 ours，只看历史四方的相对顺序；
2. 与专家当年的排序逐题比（专家键已抽好：`runs/1/_answer_key/expert_ranking.json`，
   8 题的 `四组排序` 原文 + 四方分数）；
3. 还原度就是 **G0 一致率**，脚本已备好并用假读数验过：

```bash
python3 scripts/g0_consistency.py --pack runs/1/g0_pack \
    --keys runs/1/_answer_key/g0_keys.json \
    --expert runs/1/_answer_key/expert_ranking.json \
    --out runs/1/G0一致率.md
```

| 还原度 | 怎么读本轮 ours 的名次 |
|---|---|
| 四方顺序完全一致 / 同序对 ≥0.9 | 强一致，ours 的名次可按同一把尺子解读，能与历史读数对话 |
| 0.75–0.9 | 弱一致，分差类结论必须标条件性 |
| <0.75 | **尺子不同，本轮读数只能在轮内比较，不得挂到历史刻度** |

**这里要说一句：放 base+skill 进来（你定的）恰好把这件事补全了。**
四方包（ours/base/WB/gpt）只有 3 个历史方在场，逐题只能做残缺的顺序比对；
五方包 4 个历史方全在，G0 一致率才是完整的。这个好处我上一轮没想到。
