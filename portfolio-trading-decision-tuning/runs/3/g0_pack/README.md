# 5 方盲测包

8 题 × 3 轮。**各轮必须由互不可见的会话完成**，不要在同一个会话里判两轮。
调度照 `调度清单.json`：里面每个 unit 一个 subagent，**一次性同时发起**，不要判完一轮再开下一轮。

## 你要做的

对每一题，读 `题面.md`（有附件时连 `题面附件/` 一起读），再读 `答复/` 下的几份答复
（甲 / 乙 / 丙 / 丁 / 戊，有交付文件的在 `答复/<标签>_交付文件/`），
按 `judge_prompt.md` 的三步判定顺序给出**从好到差的完整排序**，并给每一份 **1-5 分**的绝对打分。

三步顺序不得跳步：① 技术失败单列 → ② 硬门禁（见 `domain_pack.yaml` 的 `hard_gates`）
→ ③ 能力比较。领域口径以 `domain_pack.yaml` 为准。

**每条「为什么第一」和「为什么末位」都必须引答复原句 ≥10 字**，写在 `quote` 字段。
没有原句支撑的评语不计入。拿不准就在 `why_first` 里写明拿不准在哪，不要为了给出排序而编理由。


## 1-5 分打分口径

排序之外还要给每份答复一个 **1-5 的整数分**，写进 `scores`。两者都要：
排序决定胜负，分数决定差距，准出判据两个都用。

**先按能力给分**，只看这一档：

| 分 | 什么样 |
|---|---|
| 5 | 结论与关键数值全对，口径齐全，证据可追溯，缺失项处理得当，可直接交付 |
| 4 | 主体正确可用，有个别非核心瑕疵（小算术误差、覆盖略窄、表述略绝对） |
| 3 | 核心结论对，但有实质缺口：关键口径错一处、该量化的没量化、承诺的交付物不完整 |
| 2 | 有概念性错误或核心交付缺失，需要非平凡返工才能用 |
| 1 | 结论方向错，或基本无业务内容，或答非所问 |

**再按硬门禁扣**：命中 `domain_pack.yaml` 的 `hard_gates`，在能力分基础上
**降 2 分，下限 2 分**（多条只降一次）。

> 硬门禁是「大幅降位」，**不是直接判最低分**。一份内容扎实但踩了一条硬门禁的答复，
> 和一份基本没业务内容的答复，不应该拿同一个分——那样分数就没有判别力了。
> 1 分只留给能力面本身就不及格的答复。

技术失败（报错、截断、空响应）单列进 `technical_failure`，**不打分、不进能力比较**。

**分数允许打平**（真分不出就给同分，不要为了拉开差距硬给不同分）；**排序不允许并列**，必须是严格全序——分数打平时正是靠排序定胜负。
不要因为篇幅长就加分。分数与排序必须自洽：排序靠前的分不得低于排序靠后的。

## 并行怎么跑（省时间，但下面几条不能碰）

三轮之间必须隔离，所以三轮**天然就该并发**：三个 subagent 一次性同时发起，
不要等第一轮判完再开第二轮——串行等待本身就给编排方开了一条「上一轮是怎么判的」记忆通道。

**同一题的各方必须在同一次调用里判完。** 拆开就没有比较可言，这条不可并、不可分片。

本包**不分片**：一轮内的全部题目由同一个 subagent 判完（它对这一轮的尺度才是自洽的）。要分片必须由出包方在出包前决定，判分方不要自行拆。

### 不能碰的

1. **三轮同时发起，互不可见。** 三个 subagent 的输入必须逐字相同，只有 pass 目录路径不同。
2. **不许把上一轮的结论、倾向、「注意某题有坑」带给下一轮。** 并发发起正是为了让这件事没有发生的机会。
3. **编排方不读答复内容。** 只做调度、回收、格式核验；读了就会通过任务描述泄露给 subagent。
4. **不许因为三轮结果不一致就去统一口径、修正、复核后取一个。** 三轮不一致正是本包要测的东西（噪声底）。
5. **不许跨 pass 比对或按文件哈希对齐三轮的洗牌映射。** 甲乙丙丁每轮重新打乱是设计，不是错误。

## 回填

按 `templates/ranking.json` 的格式，存到 `pass<N>/case<NN>/ranking.json`。

## 注意

- 每轮的标签**重新打乱**，pass1 的甲和 pass2 的甲不是同一份答复
- 本目录**不含方别信息、不含答案键、不含专家备注**
- 篇幅长短、表格数量、语气自信、免责声明数量、用没用代码都**不计分**
