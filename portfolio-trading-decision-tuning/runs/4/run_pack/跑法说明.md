## 并行怎么跑（省时间，但下面几条不能碰）

同一遍内的各题彼此独立，**可以并发跑**，不必一题跑完再跑下一题。

本包 8 题，建议并发度 **4**（平台扛得住可以加到 8，扛不住就降，降到 1 也是对的）。
并发派活照 `任务清单.tsv`，一行一个会话。

### 不能碰的

1. **一题一会话，不要为了并行把多题塞进同一会话。** 会话共享上下文，前一题的材料会污染后一题。
2. **主版本与噪声底复跑不要同时在跑。** 两遍用的是同一个包，但在平台上是两个技能版本；两个版本同时挂着，逐题的版本校验就可能张冠李戴。先跑完一遍、校验完版本，再跑第二遍；一遍内部的各题随便并行。
3. **并发不改变「等待不算重跑」。** 占位（「已委派…后台执行中」）按抓取未完成处理：回同一会话只读补抓，不发任何消息，不重新发题。
4. **并发度只影响速度，不影响判定。** 中途不许因为「这题跑得慢」换模型、换路线、改题面或补提示——那一题就与其余题不是同一个条件了。

## 遇到「已委派…后台执行中」怎么办

平台可能先回一条占位（「已将任务委派给组织代理，后台执行中」），
真正的终稿几十分钟到数小时后才出现。**这不是答复，也不是失败。**

- 按「抓取未完成」处理：回同一会话**只读补抓**，不重新发题、不新建任务
- **补抓不是重跑**，首次有效生成仍算那一次
- **等待不算重跑。** 建议满 4 小时再去看
- 补抓时**不要向会话发任何消息**（包括「完成了吗」「请给我文件」）——
  一发消息那题就变成多轮对话，与其余题不是同一个条件。
  终稿只有发消息才拿得到就停下，如实写「需发消息才能取得，未取」
- 若最终确实停在占位 → 按**技术失败**单列，不进能力比较

## 怎么给题

每题一个全新会话，把 `题面.md` 原文作为用户消息，`附件/` 下的文件作为附件一起给。
题面里出现的时点、口径、约束一律照抄，不要改写、不要补充、不要提示。
多轮追问的题按题面里写的轮次走；题面没写就单轮。

## 回收

```
runs/<n>/responses/ours_case<NN>.md              ← 正文，原样保存，不要清理格式
runs/<n>/response_files/ours_case<NN>/           ← 该题交付的全部文件
runs/<n>/responses_rerun/ours_case<NN>.md        ← 第 2 遍（噪声底）
```

正文请**原样保存**：过程独白、报错、截断都不要删——判定的第一步就是识别技术失败，
清理过的输出会让技术失败看起来像正常答复。

交付件回执请把**页面可见几件**与**实际下载成功几件**分开报：
只在本机沙箱可见属于「抓不到」，页面确实没有属于「没有」——判分时不是一回事。
